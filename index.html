Problem · 문제
스킬·코스트·체력·버프·필살기·교체·보주 등 핵심 정보가 한 화면에 집중되는 구조. 일반·PVP·던전·레이드 전투 모드마다 표시 정보가 달라 모드별 화면을 개별 제작하면 개발 공수가 크게 늘어남.
Approach · 접근
정보를 상시·조건·요청·숨김 4단으로 분류해 우선순위 프레임워크를 수립하고, 모드별 UI는 베이스 템플릿 위에 가변 모듈을 추가/제거하는 방식으로 분리. 개발팀이 화면 단위가 아닌 모듈 단위로 재사용할 수 있는 구조로 정리했습니다.
Output · 산출물
  • 전투 준비 → 진행 → 결과 전체 UX 플로우
  • 전투 HUD 시안 (스킬·필살기·보주·코스트)
  • 자동 전투 / 전투 위임 UX 플로우
  • 모드별 공통 템플릿 + 모듈 가이드
Outcome · 결과
출시 전 단계에서는 유저 지표보다 기획 변경 대응성과 개발 재사용성을 우선 지표로 삼았습니다. 정보 우선순위 프레임워크는 이후 탐험·레이드에도 동일 적용했고, 1보주 → 2보주 기획 변경 시 레이아웃 재설계 범위를 최소화했습니다.

Key Takeaway
복잡한 전투 정보를 플레이 중 의사결정에 필요한 단위로 재구성했고, 개발팀이 컴포넌트를 재사용할 수 있는 구조로 설계했습니다.

화면을 새로 띄우지 않고 동일 프레임 내 상태·CTA만 변화
Problem · 문제
글로벌 벤 → 픽 → 2차 벤 → 출전 순서 결정으로 이어지는 다단계 드래프트 플로우. 단계마다 화면이 통째로 바뀌면 유저가 현재 단계 맥락을 잃기 쉽고, 시간 제한까지 존재해 긴장감과 명확성이 동시에 요구됨.
Approach · 접근
매 단계 새 화면 대신 동일 프레임 안에서 상태와 CTA만 변하도록 설계. 스텝 인디케이터로 현재 위치를 명확히 하고, 시간 제한은 테두리·배경 색상 변화로 압박 없는 긴장감을 전달.
Output · 산출물
  • 랭크 매치 / 친선전 / 드래프트 플로우
  • 단계별 선택·검색·랭킹·보상 화면
  • 아레나 광장 · 친선전 초대 UX
  • 콜로세움 시즌 보상 · 명예의 전당
Outcome · 결과
경쟁 콘텐츠의 다단계 규칙을 상태 변화 중심 인터랙션으로 변환하는 방식이 이후 길드전·레이드 설계에도 동일 적용됨. 화면 전환을 줄여 개발 구현 범위도 함께 축소되는 효과.
"
Key Takeaway
복잡한 경쟁 콘텐츠 규칙을 단계 이동 없이 상태 변화로 처리해, 유저가 플로우를 잃지 않고 따라갈 수 있게 설계했습니다.
